## 1.1 Java 的地位

### 1.1.1 网络地位

**先理解“网络应用”的运行环境。** 网络中的客户端与服务器可能运行在不同 CPU 架构和操作系统上；如果软件只能依赖某一操作系统的原生指令，那么跨环境迁移成本会增加。Java 的重要设计目标之一，就是让同一份程序更容易在多种受支持的平台上运行。

Java 常见应用领域包括：服务器端业务逻辑、Web 后端接口、企业信息系统、分布式服务、工具软件及部分移动/嵌入式开发。它并不等于“网站前端语言”；网页中的 JavaScript 和 Java 是两门不同的语言。

**必须分清三个层次：**

1. **通信层**：HTTP、TCP 等协议负责跨机器传输数据。
2. **应用层**：Java 程序处理数据、权限、业务规则等。
3. **运行层**：操作系统上的 JVM 执行 Java 程序编译得到的字节码。

**例：** 浏览器发出“查询成绩”的 HTTP 请求；Java 服务端接收请求、查询数据、返回 JSON；浏览器再渲染结果。浏览器未必运行 Java，Java 可以只在服务端运行。

**易错点**：Java 与网络有关，不意味着每个 Java 程序必须联网；本地命令行程序完全可以不使用网络。

### 1.1.2 语言地位

Java 是**静态类型、面向对象、通用目的**的编程语言，具有明确的类型规则、异常处理机制和丰富的标准类库。静态类型表示：变量、表达式、方法的类型约束通常在编译阶段就会被检查，例如将字符串直接赋给整数变量会触发编译错误。

**Java 的源代码并不会直接变成当前 CPU 可执行的本机程序文件。** 典型流程是源文件编译成字节码，再由运行环境加载与执行。运行时可解释执行，也可通过即时编译（JIT）把热点字节码编译为机器码。于是“Java 是纯解释型语言”这一说法不准确。

区分三个概念：

| 概念 | 主要含义 | 常见文件/工具 |
| --- | --- | --- |
| 源代码 | 人编写的 Java 程序文本 | Hello.java |
| 字节码 | Java 编译器生成的中间表示 | Hello.class |
| 运行时执行 | JVM 对字节码进行加载、校验与执行 | java 命令、JVM、JIT |

**要点**：编译器负责识别语法和类型错误；运行时仍可能出现空指针、数组越界等异常。**能成功编译 ≠ 一定能正确运行。**

### 1.1.3 需求地位

Java 广泛用于需要长期维护、模块化开发和跨系统协作的软件。为什么在工程中常见：

- **语言与类库成熟**：常用容器、I/O、网络、并发和数据库访问都有成体系的接口。
- **工具链完善**：JDK、IDE、构建工具与自动化测试工具能形成稳定工作流。
- **可维护性**：类、接口、包和访问控制有利于分层、复用与多人协作。
- **兼容性目标明确**：字节码和 Java API 带来跨平台能力，但不是无限兼容。

需要保持客观：Java 并非所有任务的最优解。浏览器交互通常用 JavaScript/TypeScript；底层驱动或特殊实时环境可能使用 C/C++、Rust 等。选语言要看场景。

**自检**：为什么“网页使用 JavaScript”不能推导出“浏览器直接执行 Java 源程序”？

## 1.2 Java 的特点

### 1.2.1 简单

“简单”指**相对于部分传统语言，减少了某些复杂且易误用的语言机制**，不等于零基础毫无难度。

典型体现：

- 不让程序员像 C 一样直接使用裸指针算术操作对象地址。
- 普通对象的内存回收主要由垃圾回收机制管理，但文件、Socket 等外部资源仍需主动关闭。
- 使用统一的类和对象模型组织代码；不存在 C++ 式多重“类继承”，但一个类可以实现多个接口。
- 标准库封装了大量常见工作，例如字符串、集合、文件读写。

**容易混淆**：垃圾回收解决的是对象内存管理，不会保证文件句柄、数据库连接及时关闭。后续学习 I/O 时需掌握 try-with-resources。

### 1.2.2 面向对象

理解四个层次，不要只背三个词：

1. **类（class）**：描述一种对象具有哪些状态（字段）和行为（方法），可以看成类型定义。
2. **对象（object）**：按某个类创建的实例，各实例通常维护自身的实例字段。
3. **封装**：限制不应随意修改的内部状态，公开经过设计的方法或接口。
4. **继承与多态**：复用并扩展父类能力；同一父类型引用可以指向不同实际子类型对象，调用可重写方法时由运行时选择相应实现。

类是蓝图，对象是实例，但**类不是单纯的“容器”，还包含对状态及行为的约束**。

原创示例（非教材原代码）：

~~~java
class Book {
    private String title;

    Book(String title) {
        this.title = title;
    }

    void printTitle() {
        System.out.println(title);
    }
}
~~~

- title 是每个 Book 对象自己的实例字段。
- 构造方法 Book(String title) 用于初始化新对象。
- private 保护字段，调用者不能任意直接访问该字段。
- printTitle() 是通过对象调用的实例方法。

上面的例子只是为了提前建立概念；构造方法、访问控制、继承和多态在第 4—6 章详细学习。

### 1.2.3 与平台无关

经典目标是 **Write Once, Run Anywhere（一次编写，到处运行）**。其关键不是 JVM 完全一样，而是：

1. 在一台机器上用 javac 编译成符合规定格式的 .class 字节码。
2. 目标机器安装**支持该字节码版本和所使用 API 的 Java 运行环境**。
3. JVM 在目标系统上加载并执行字节码。

~~~text
                 Java 源文件（.java）
                          |
                       javac
                          v
                   字节码（.class）
                     /     |     \
                    v      v      v
              Windows    Linux    macOS
                JVM       JVM      JVM
                    \      |      /
                      程序行为
~~~

**限制条件**：

- 不同 JDK 版本的类文件版本可能不兼容。高版本 javac 生成的字节码，旧 JVM 不一定能运行（常见报错 UnsupportedClassVersionError）。
- 程序如果依赖本机动态库、操作系统文件路径或特定 GUI 能力，依然可能出现平台差异。
- “跨平台”说的是**在合适运行环境下的可移植性**，而不是任何设备均能无条件执行。

**考试常问**：Java 能跨平台主要靠什么？答：面向统一字节码规范的编译过程，以及不同平台的 JVM 实现与标准运行环境。

### 1.2.4 多线程

线程是进程中的一个执行单元。一个 Java 进程可包含多个线程，在一定条件下并发推进任务，在多核 CPU 上也可能并行运行。

**并发（concurrency）**：多个任务在同一时间段交错推进；**并行（parallelism）**：多个任务在同一时刻实际运行。两者不能直接画等号。

多线程可能让程序保持响应、同时处理多项任务，但也会带来共享数据竞争、顺序不确定和死锁问题。

例如：两个线程同时对共享计数器执行“读取→加一→写回”，如果没有同步，可能丢失更新。所以 **线程越多不一定越快，更不意味着结果天然正确**。第 12 章专门展开。

### 1.2.5 动态

“动态”不是指“Java 没有类型检查”。Java 仍是静态类型语言。

Java 运行时可以按需加载类、基于实际类型决定调用哪个重写方法，并通过反射在运行时查询类、构造方法、字段等元信息。这些特性支撑插件式加载、框架的对象管理等设计。

**动态绑定**：例如变量声明类型为 Animal，实际指向 Cat 对象，调用可重写的普通实例方法时，最终执行 Cat 的实现。静态方法、字段访问以及被 final 等约束的方法，不要简单按普通实例方法的多态规则理解。

## 1.3 安装 JDK

### 1.3.1 平台简介

先区分 **Java SE、Java EE/Jakarta EE、Java ME** 与 **JDK、JRE、JVM**，两套分类并非同一回事。

| 名称 | 它是什么 | 解决什么问题 |
| --- | --- | --- |
| Java SE | Java 标准平台及基础 API | 一般 Java 程序的基础开发与运行 |
| Java EE / Jakarta EE | 企业应用相关的一组规范和平台 | 服务端企业级开发 |
| Java ME | 面向受限设备的 Java 平台体系 | 部分嵌入式及受限设备环境 |
| JVM | Java 虚拟机 | 加载、验证、执行字节码 |
| JRE（传统术语） | Java 运行环境，主要由 JVM 和运行库组成 | 运行程序 |
| JDK | Java 开发工具包，包括编译和开发工具及运行所需组件 | 编译、调试、运行与开发 |

**关系**：

~~~text
JDK（开发工具包）
├── javac / java / javap / javadoc 等开发与运行工具
├── 运行库与 Java API
└── JVM（执行字节码）

传统教材常画：JDK ⊃ JRE ⊃ JVM
（现代 JDK 的打包形式不同，不一定包含独立的 jre/ 目录）
~~~

**三个常见问题**：

- **javac 是 JVM 吗？** 不是。javac 是编译器，java 命令启动运行环境。
- **只安装 JRE 能编写并编译 Java 程序吗？** 传统 JRE 通常不包含 javac，不适合完整开发。
- **为什么安装了 JDK 还提示找不到 javac？** 可能是 PATH 没设置、终端未重启，或环境变量指向了错误目录。

> 版本说明：本书以 **JDK 14** 为教学背景，讲解时会标识这个历史版本。实际安装可选择受支持的 JDK 版本，但课堂代码兼容性需要留意差异。下面命令以常见 JDK 命令行用法为准。

### 1.3.2 安装 Java SE 平台

安装思路不复杂，核心是获得一个合法的 JDK 并确认它能够运行：

1. 从受信任的发行方获取所需版本的 JDK（如 Eclipse Temurin、Oracle JDK 等）。
2. 安装或解压到固定目录，避免随意删除安装位置。
3. 打开新终端分别运行：

~~~bash
java -version
javac -version
~~~

- java -version 表示**运行工具**是否可用及版本。
- javac -version 表示**编译工具**是否可用及版本。
- 两个版本应按项目预期匹配；如果输出版本不一致，检查 PATH 中是否还有旧 JDK。

**典型问题**：java -version 正常而 javac -version 报“命令不存在”，经常说明只配置了运行工具或 PATH 不包含 JDK 的 bin 目录。

### 1.3.3 系统环境的设置

操作系统通过 **PATH 环境变量**查找命令；JAVA_HOME 通常用于让工具明确知道 JDK 的安装目录。请区分“工具在哪”和“代码在哪”。

Windows 中，一种常见配置是：

~~~text
JAVA_HOME = C:\Program Files\Java\jdk-xx
Path 新增 = %JAVA_HOME%\bin
~~~

macOS/Linux 中，路径因 JDK 发行版和安装方式而异，可以在 shell 配置里设置 JAVA_HOME 与 PATH；但不要盲目复制 Windows 路径。

**CLASSPATH** 用来影响 Java 类加载器查找应用类/库的位置。初学阶段通常**不需要全局设置 CLASSPATH**，使用命令行的 -cp 或 -classpath 显式指定更清楚。把所有路径全局拼在一起反而容易出错。

常见排错顺序：

1. 确认 JDK 安装目录是否包含 bin/javac。
2. 在终端确认 java、javac 版本。
3. 排查 PATH 是否同时指向多个 JDK。
4. 新开终端让环境变量生效。
5. 确认文件所在目录与命令执行目录是否对应。

## 1.4 Java 程序的开发步骤

**最基本的三阶段**：编写源文件 → 编译源文件 → 运行程序。不要把编译成功、启动成功、业务正确混为一谈。

~~~text
① 编写 Hello.java
       │ 纯文本 Java 源程序
       ▼
② javac Hello.java
       │ 编译检查（词法/语法/类型等）
       ├── 错误 → 修改源码，再编译
       ▼
   Hello.class（字节码）
       │
③ java Hello
       │ JVM 加载和执行入口类
       ├── 运行异常 → 分析堆栈、修改代码
       ▼
   控制台输出与程序结果
~~~

**编译错误示例**：缺少分号、变量未声明、类型不匹配、public 类与文件名不对应。编译器在生成合法字节码前会拒绝这些错误。

**运行错误示例**：试图访问空对象、数组下标越界、程序需要的类找不到。这些问题可能只有程序实际运行到相应位置时才出现。

**逻辑错误示例**：程序正常结束却得出了错误答案。编译器一般无法仅凭语法推断业务意图；需要手工测试或自动化测试。

## 1.5 简单的 Java 应用程序

### 1.5.1 源文件的编写与保存

下面是**本站原创的最小演示**，不是书中样例源码：

~~~java
public class Welcome {
    public static void main(String[] args) {
        String course = "Java";
        System.out.println("开始学习 " + course);
        System.out.println("第一章");
    }
}
~~~

**必须逐项理解：**

- **public class Welcome**：定义名为 Welcome 的公开类。源文件必须命名为 Welcome.java，大小写需一致。
- **花括号 { }**：界定类体、方法体等代码块，不是可省略的装饰。
- **public static void main(String[] args)**：传统 Java 应用程序常见入口方法声明。public 表示可访问，static 表示该方法属于类而无需创建对象，void 表示不返回值，String[] args 用于接收命令行参数。
- **System.out.println(...)**：System 是标准库中的类，out 是标准输出流，println 输出内容后换行。
- **String course = "Java";**：声明字符串变量并初始化；右侧是字符串字面量。
- **分号 ;**：结束这里的变量声明和方法调用语句。

**编译单元不是运行单位。** 一个 .java 文件可包含多个顶层类，但一个源文件中至多一个 public 顶层类，且文件名要与该 public 类名一致。本章先用一个源文件、一个类，后续再讨论多类协作。

**常见失误**：使用中文分号；把双引号写成中文引号；文件扩展名其实是 .java.txt；Windows 隐藏文件扩展名导致看错。

**原书对应位置**：第 1 章 §1.5.1《源文件的编写与保存》。**原书代码：留白**；印刷页码、例题编号：待核实第 6 版页面。

### 1.5.2 编译

把 Welcome.java 放在当前工作目录，使用命令：

~~~bash
javac Welcome.java
~~~

如果编译成功，通常会产生 Welcome.class。**成功编译不一定打印“成功”字样**，很多情况下命令执行结束且没有错误就是正常表现。

更完整的理解：

- javac 读取源文件。
- 检查语法结构、类型及符号解析。
- 将合法类编译为字节码类文件。
- 如果该源文件定义多个类，可能生成多个 .class 文件。

**常见编译错误定位**：

| 现象 | 首先检查 |
| --- | --- |
| cannot find symbol | 类名/变量名是否写错，是否在作用域内 |
| ';' expected | 是否漏掉分号或写错括号 |
| class ... is public, should be declared in a file named ... | 文件名与 public 类名 |
| incompatible types | 赋值或调用参数的类型是否匹配 |

**注意**：一旦修改源文件，需要重新运行 javac；否则执行的可能仍是旧 .class 文件。

### 1.5.3 运行

编译成功后，使用：

~~~bash
java Welcome
~~~

预期输出：

~~~text
开始学习 Java
第一章
~~~

这里 **java 后面通常写类名 Welcome，不写 Welcome.java，也不写 Welcome.class**（本书传统的“先编译再执行字节码”教学流程）。

为什么如此？

1. java 启动 JVM。
2. 类加载机制寻找 Welcome 对应的字节码。
3. JVM 验证、链接并初始化类，在符合规则的入口方法处开始执行。
4. 程序完成后结束；System.out.println 会把字符输出到控制台。

**补充对照**：java Welcome.java 属于较新 JDK 中支持的“源文件模式”用法，不应与本节的 java Welcome 命令混淆。按教材学习时优先掌握传统三步法。

如果看到 **Could not find or load main class Welcome**，先核对工作目录、类名大小写、包声明、类路径；如果看到 **Main method not found**，检查 main 的声明是否正确。

**原书对应位置**：第 1 章 §1.5.2、§1.5.3《编译》《运行》。**原书代码：留白**；页码、原例号：待核实。

## 1.6 Java 反编译

### 概念先分清：反汇编和反编译

- **反汇编字节码（disassemble）**：把 .class 中的字节码指令展示成相对可读的指令列表，例如 javap -c。
- **反编译（decompile）**：尝试从字节码重建较接近 Java 语言的源代码，例如第三方 Java 反编译工具。

两者不是一回事，也**不能保证恢复原始源码**。编译过程中，注释、原始排版和部分局部变量信息可能被删除；反编译生成的变量名或代码结构可能不同。

在已经有 Welcome.class 的情况下，可以尝试：

~~~bash
javap Welcome
javap -c Welcome
javap -verbose Welcome
~~~

- javap Welcome：观察类的可见成员签名。
- javap -c Welcome：观察方法字节码指令。
- javap -verbose Welcome：查看更多 class 文件结构、常量池与版本等细节。

**一个关键认识**：源代码中一条 Java 语句，未必对应一条 JVM 指令；不同编译器或不同优化选项可能产生不同的字节码布局。

## 1.7 编程风格

编程风格通常不改变正确程序的含义，却显著影响可读性、协作效率与调试成本。

### 1.7.1 Allmans 风格

Allman（教材目录写作 Allmans）风格通常把左花括号放在下一行：

~~~java
class Demo
{
    public static void main(String[] args)
    {
        System.out.println("Hello");
    }
}
~~~

**特点**：花括号在纵向上对齐，容易直接观察代码块范围；代价是占用较多行。

### 1.7.2 Kernighan 风格

Kernighan/Ritchie（常写为 K&R）风格通常把左花括号放在控制头或声明的末尾：

~~~java
class Demo {
    public static void main(String[] args) {
        System.out.println("Hello");
    }
}
~~~

**特点**：更紧凑。与上一示例相比，程序功能没有变化。应优先保持项目内一致，不必把风格差异当成算法差异。

### 1.7.3 注释

Java 常见的三种注释形式：

~~~java
// 单行注释

/* 多行注释：
   可以跨越多行 */

/**
 * 文档注释：通常用于公开类、方法等 API 文档。
 */
~~~

**注意**：

- 编译器不会把注释当作可执行语句。
- 文档注释可与 javadoc 工具配合生成 API 文档。
- 注释应说明意图、约束或容易误解的逻辑，而不是机械重复每一条赋值语句。
- 普通块注释 /* ... */ 不能直接嵌套同类块注释。

**易错点**：在字符串内部出现 // 不会开启注释，例如 "https://example.com" 仍是字符串。

## 1.8 Java 之父——James Gosling

James Gosling 通常被称为 Java 之父，是 Java 最初设计和研发的重要人物之一。Java 起源于 Sun Microsystems 的相关项目，后来发展成为面向多种运行平台的通用编程语言。

学习这段历史的意义不只是记人名，而是理解其设计背景：面对不同硬件和系统，如何提供相对统一的语言、类库和运行机制。Java 最重要的工程选择之一，就是围绕字节码和虚拟机建立生态。

**史实与概念辨析**：Java、JavaScript 名称相似，但不是同一种语言，也不是“Java 的简化版”。

## 1.9 小结：把本章知识串成一条线

理解 Java 的最小闭环：

1. **为什么有 Java**：降低部分软件跨系统维护和开发成本，提供成熟的工程开发平台。
2. **语言有什么特点**：静态类型、面向对象、平台可移植性、多线程、运行时动态能力。
3. **开发用什么**：JDK 提供 javac 等工具；JVM 负责执行字节码。
4. **程序如何跑起来**：编写 .java → javac 编译成 .class → java 启动程序。
5. **如何排错**：分清编译错误、运行异常和逻辑错误。
6. **如何保证代码质量**：统一格式、合理注释、明确的类命名与文件管理。

**概念对照表**：

| 常见混淆 | 正确判断 |
| --- | --- |
| Java = JavaScript | 错，两门不同语言 |
| JDK = JVM | 错，JDK 包含开发工具和运行相关组件 |
| javac 负责运行代码 | 错，javac 负责编译 |
| JVM 等于操作系统 | 错，JVM 是运行字节码的虚拟机实现 |
| 编译成功就一定逻辑正确 | 错，还需测试 |
| 平台无关意味着绝无兼容问题 | 错，JDK/API/本地依赖等均会影响 |
| javap 能百分百恢复原始源码 | 错，它主要展示类结构和字节码等 |

**本章结束后应该能独立回答**：Java 怎么通过 JVM 达到跨平台目标？JDK、JRE、JVM 的区别是什么？main 方法为什么要这样写？java Welcome 与 javac Welcome.java 的作用为何完全不同？
